# VS-03 — Admin Dashboard

**Project:** Photography Showcase Platform
**Vertical Slice:** VS-03 of 17
**Module:** Admin Dashboard
**Depends on:** VS-01 Foundation + VS-02 Admin Authentication

The goal of this slice is to turn the authenticated `/admin` area into the photographer's **central control center**.

The photographer should be able to open the dashboard and immediately understand:

* How much content is in the website
* How many projects are published
* How many photos are available
* Which content needs attention
* How many visitor inquiries have arrived
* What was recently changed
* Quickly navigate to the important CMS functions

---

# 1. Slice Goal

The final flow should be:

```text
                    ADMIN LOGIN
                         │
                         ↓
                  Authentication
                         │
                         ↓
                 /admin/dashboard
                         │
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
    Overview         Quick Actions    Recent Activity
        │                │                │
        ↓                ↓                ↓
   Statistics       Manage Content    Content Updates
        │
        ├── Photos
        ├── Projects
        ├── Categories
        ├── Messages
        └── Website Status
```

---

# 2. Dashboard Responsibilities

The dashboard is **not** the place where all content is managed.

Instead, it should provide:

### Overview

A quick summary of the entire photography website.

### Navigation

Fast access to major CMS modules.

### Monitoring

Show content and inquiry status.

### Quick actions

Allow the photographer to perform common actions without navigating through multiple screens.

### Activity

Show recent changes made inside the CMS.

# 6. Dashboard Design Direction

Because this is a product you want to **sell to photographers**, the admin dashboard should feel like a professional SaaS CMS rather than a generic CRUD panel.

### Design characteristics

* Minimal
* Premium
* Spacious
* Fast
* Clean typography
* Clear hierarchy
* Subtle animations
* Strong visual feedback
* Responsive

Avoid excessive:

* Gradients
* Shadows
* Neon colors
* Unnecessary charts
* Decorative animations

The **public website** can be artistic and cinematic.

The **admin dashboard** should be highly practical.

# 32. Important Architecture Decision

**Do not make dashboard statistics manually maintained counters.**

Bad:

```text
total_photos = 128
```

and then manually incrementing it.

Instead:

```text
COUNT(photos)
```

or an equivalent database query.

This prevents dashboard numbers from becoming inconsistent with actual content.

---

# 33. Performance

Dashboard should be fast.

Avoid:

```text
Load entire photo table
Load entire project table
Load entire message table
```

just to calculate counts.

Use database aggregation:

```text
COUNT
GROUP BY
LIMIT
ORDER BY
```

where appropriate.

---

# 34. Caching

For VS-03, caching is **optional**.

Because the dashboard data is relatively lightweight, direct database aggregation is acceptable.

Later, if the platform grows significantly, dashboard statistics can be cached.

---

# 35. Security

Dashboard APIs must require authentication.

Example:

```text
GET /api/v1/dashboard/stats
              │
              ↓
       authMiddleware
              │
              ↓
       Dashboard Service
```

Never expose:

```text
admin information
internal activity logs
message statistics
CMS statistics
```

through public APIs.

# 40. Business Rules

### BR-DASH-001

Only authenticated administrators can access the dashboard.

### BR-DASH-002

Dashboard statistics must represent current database state.

### BR-DASH-003

Statistics must not expose private information to public visitors.

### BR-DASH-004

Activity records must belong to an authenticated admin action.

### BR-DASH-005

Deleting content should create an appropriate activity record where applicable.

### BR-DASH-006

Dashboard failure in one widget must not prevent other widgets from rendering.

### BR-DASH-007

Quick actions must only navigate to features the authenticated admin can access.

### BR-DASH-008
