# VS-06 — Project / Gallery Management

**Project:** Photography Showcase Website
**Vertical Slice:** VS-06
**Module:** Project / Gallery Management
**Depends on:** VS-04 Category Management + VS-05 Photo Management

---

## 1. Slice Goal

VS-06 introduces the **Project/Gallery layer** of the photography website.

The key idea is:

> A photographer shouldn't only upload individual photos. They should be able to organize a collection of photos into beautiful, meaningful projects/galleries that visitors can browse.

For example:

```text
Projects
│
├── Royal Wedding — Mumbai
│   ├── Photo 01
│   ├── Photo 02
│   ├── Photo 03
│   └── Photo 04
│
├── Fashion Editorial — Pune
│   ├── Photo 01
│   ├── Photo 02
│   └── Photo 03
│
├── Pre-Wedding — Goa
│   ├── Photo 01
│   ├── Photo 02
│   └── Photo 03
│
└── Travel Stories — Rajasthan
    ├── Photo 01
    ├── Photo 02
    └── Photo 03
```

This becomes the foundation for the **premium public portfolio experience**.

---

# 2. Project vs Photo

The distinction should be very clear.

### Photo

An individual image:

```text
Bride Portrait.jpg
```

### Project

A curated story/collection:

```text
Royal Wedding — Mumbai
```

containing:

```text
25 photographs
```

So:

```text
Category
   ↓
Project
   ↓
Photos
```

Example:

```text
Wedding
   ↓
Royal Wedding — Mumbai
   ↓
30 Photos
```

# 16. Project → Photos Relationship

A project contains many photos.

Recommended relationship:

```text
projects
    │
    │ 1
    │
    ↓
project_photos
    │
    │ *
    ↓
photos
```

Use a junction table:

```text
project_photos
```

rather than putting:

```text
photos.project_id
```

directly on the photo.

---

# 17. Why Junction Table?

Because the same photograph may potentially be reused in different collections.

Example:

```text
Photo: Bride Portrait
       │
       ├── Royal Wedding
       └── Featured Portraits
```

This gives the photographer much more flexibility.

# 18. Project Photos Schema

```text

```

so the same photo cannot accidentally be added twice to one project.

# 47. Important Business Rules

### BR-PROJECT-001

Only authenticated admins can create or manage projects.

### BR-PROJECT-002

Project title is required.

### BR-PROJECT-003

Project slug must be unique.

### BR-PROJECT-004

Every project must have a valid category.

### BR-PROJECT-005

Only active categories may be assigned to new projects.

### BR-PROJECT-006

A project cannot contain the same photo twice.

### BR-PROJECT-007

Removing a photo from a project must not delete the photo.

### BR-PROJECT-008

Cover photo must belong to the project.

### BR-PROJECT-009

Draft projects must not appear publicly.

### BR-PROJECT-010

Hidden projects must not appear publicly.

### BR-PROJECT-011

Projects belonging to inactive/hidden categories must not appear publicly.

### BR-PROJECT-012

Project ordering must persist.

### BR-PROJECT-013

Gallery photo ordering must persist.

### BR-PROJECT-014

Important project actions must be logged.

---

# 48. Public Visibility Rule

A project can appear publicly only if:

```text
project.is_published = true
AND
project.is_visible = true
AND
category.is_active = true
AND
category.is_visible = true
```

Then its photos should also satisfy:

```text
photo.is_published = true
AND
photo.is_visible = true
```

This creates a safe content hierarchy.
