## 7.2 Demo Account

Create a restricted demo account with:

* Limited admin permissions

* No access to production secrets

* No access to real client enquiries

* No access to system-level settings, if possible

Example:

```
Role: Demo Admin
Access: Content preview and basic CMS
Restrictions: No secrets, no user management, no system configuration
```

## 7.3 Demo Reset

If the product is used for sales demonstrations, provide a reset mechanism that can:

* Restore demo projects

* Restore sample categories

* Restore sample settings

* Remove test enquiries

* Reset demo changes

The reset function must never be available to normal public visitors.

# 9. Production Configuration

## Required Configuration

Verify:

* Production application URL

* Database URL

* Authentication secret

* Storage credentials

* Email provider credentials

* CORS origins

* Public frontend URL

* Backend API URL

* Analytics configuration

* CAPTCHA configuration

* Cache configuration

* Error monitoring configuration

* File upload limits

* Allowed image formats

## Environment Rules

* Never commit `.env` files.

* Use separate secrets for staging and production.

* Do not use development database credentials in production.

* Do not use test email recipients in production.

* Do not expose server secrets to the frontend.

* Do not enable verbose production errors.

* Do not leave demo data in a real client environment.

# 11. Database Release Checklist

Before deployment:

* All migrations are committed

* Migration order is correct

* Production backup is available

* Required indexes exist

* Foreign keys are valid

* No test records remain

* Default settings are inserted

* Required admin user exists

* Sensitive columns are protected

* Database connection pooling is configured

* Database timezone is correct

* Database cleanup policy is defined

# 12. Storage and Media Release Checklist

* Public media bucket is configured

* Private media bucket is protected

* Upload permissions are restricted

* Public read permissions expose only approved media

* Original files are protected where required

* Optimized variants exist

* Broken media references are identified

* File size limits are active

* Storage usage monitoring is enabled

* Backup or recovery process is defined

# 15. Backup and Recovery

## Backup Requirements

Create backups for:

* Database

* Media metadata

* Original media files

* Site settings

* Email templates

* SEO configuration

## Backup Schedule

Recommended:

* Daily database backup

* Weekly full backup

* Before every production migration

* Before major content deletion

* Before changing storage configuration

## Recovery Testing

Verify that the team can:

1. Restore the database.

2. Restore media metadata.

3. Restore site settings.

4. Reconnect media files.

5. Recreate admin access.

6. Verify public pages after recovery.

A backup is not considered reliable until restoration has been tested.
