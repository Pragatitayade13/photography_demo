# VS-16 — Full Admin/Public Integration & Production QA

## 1. Slice Overview

### Goal

Connect and validate the complete photography showcase website so that every major admin action correctly affects the public website, all modules work together, and the product is ready for final deployment.

This slice focuses on:

* End-to-end integration

* Admin-to-public data synchronization

* Complete user journeys

* Cross-module validation

* Regression testing

* API contract verification

* Role and permission testing

* Responsive testing

* Accessibility testing

* Production environment testing

* Bug fixing and release readiness

# 6. Integration Requirements

## 6.1 Admin Changes Must Reflect Publicly

When an admin:

* Publishes a project

* Changes a project title

* Updates a project cover image

* Changes a category

* Updates the photographer profile

* Changes navigation

* Updates contact information

* Changes branding

* Updates SEO metadata

The public website must reflect the change without requiring manual database changes.

## 6.2 Draft and Published Rules

Public APIs must return only:

* Published projects

* Active categories

* Visible about sections

* Public media

* Active navigation items

* Public contact settings

* Published SEO data

Admin APIs may return drafts and archived content according to permissions.

## 6.3 Cache Invalidation

After content updates:

* Clear affected cache entries

* Refresh public API results

* Refresh sitemap data where required

* Refresh social preview metadata where required

* Prevent stale content from remaining visible indefinitely

# 7. End-to-End Admin Workflow

## Step 1 — Admin Login

1. Open `/admin/login`.

2. Enter valid credentials.

3. Submit login form.

4. Verify successful redirect to `/admin/dashboard`.

5. Verify session is stored securely.

6. Verify unauthorized pages cannot be accessed after logout.

## Step 2 — Configure Website

1. Open `/admin/settings`.

2. Update site name.

3. Upload logo and favicon.

4. Update photographer name and tagline.

5. Add public email and phone number.

6. Configure social links.

7. Update navigation items.

8. Save changes.

9. Open the public website.

10. Verify all changes appear correctly.

## Step 3 — Create Category

1. Open `/admin/categories`.

2. Create a category such as `Wedding`.

3. Add description and display order.

4. Activate the category.

5. Verify it appears in project creation.

6. Verify it appears in public filters if configured as visible.

## Step 4 — Upload Media

1. Open `/admin/media`.

2. Upload a valid image.

3. Verify upload progress.

4. Verify image processing status.

5. Verify thumbnails and responsive variants.

6. Add alt text and caption.

7. Mark the media as public.

8. Verify the image can be selected in a project.

## Step 5 — Create Project

1. Open `/admin/projects`.

2. Create a new project.

3. Add title, slug, description, location, date, and category.

4. Select a cover image.

5. Attach gallery images.

6. Add SEO metadata.

7. Configure featured and related project settings.

8. Save as draft.

9. Verify it does not appear publicly.

10. Publish the project.

11. Verify it appears on `/portfolio`.

## Step 6 — Validate Public Project

1. Open the project card.

2. Verify title and cover image.

3. Verify project description.

4. Verify category and metadata.

5. Open the gallery.

6. Verify fullscreen viewer.

7. Verify next and previous navigation.

8. Verify image captions.

9. Verify sharing controls.

10. Verify project enquiry CTA.

11. Verify related projects.

12. Verify analytics event tracking.

## Step 7 — Submit Enquiry

1. Open the project enquiry CTA.

2. Verify project information is prefilled or passed through the URL.

3. Enter visitor information.

4. Submit the enquiry.

5. Verify validation messages.

6. Verify success confirmation and reference number.

7. Verify duplicate submission protection.

8. Verify admin notification.

9. Verify visitor confirmation email if enabled.

## Step 8 — Manage Enquiry

1. Open `/admin/enquiries`.

2. Verify the new enquiry appears.

3. Open the enquiry detail page.

4. Update priority.

5. Add an internal note.

6. Change status to `CONTACTED`.

7. Verify activity history.

8. Verify optional status notification.

9. Change status to `CONFIRMED`.

10. Verify dashboard counters update.

* Correct validation behavior

* Correct error status

* Correct pagination

* Correct filtering

* Correct authorization

```
{
  "success": true,
  "data": {},
  "message": "Operation completed successfully."

```

JSON

```
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",

}
```

# 13. Accessibility QA

## Keyboard Testing

Verify that users can:

* Navigate through all controls with `Tab`

* Activate buttons with `Enter` or `Space`

* Close modals with `Escape`

* Navigate galleries with arrow keys

* Submit forms using the keyboard

* Reach every interactive element

## Screen Reader Testing

Verify:

* Images have meaningful alt text

* Decorative images are ignored

* Form fields have labels

* Validation errors are announced

* Modal titles are announced

* Loading states are communicated

* Buttons have meaningful names

* Navigation landmarks are present

## Visual Accessibility

* Sufficient text contrast

* Visible focus indicators

* No information conveyed by color alone

* Text remains readable when enlarged

* Buttons are large enough for touch

* No flashing animation

* Reduced-motion preference is respected

# 14. Security QA

## Authentication

* Invalid credentials are rejected

* Expired sessions are rejected

* Logout invalidates access

* Admin routes cannot be accessed directly without authentication

* Role restrictions are enforced on the backend

* Failed login attempts are logged

## Authorization

* Admin cannot access unauthorized resources

* Public APIs exclude private data

* Draft projects are not publicly visible

* Private media cannot be accessed through guessed URLs

* Internal notes are never returned publicly

* Notification logs are protected

## Input Security

* HTML injection is blocked

* Script injection is blocked

* SQL injection is prevented

* Unsafe URLs are rejected

* File path traversal is prevented

* Invalid UUIDs are rejected

* Oversized requests are rejected

## Privacy

* Enquiry messages are not sent to analytics

* Admin notes are not included in visitor emails

* API responses do not expose secrets

* Logs do not expose passwords or tokens

* Private client galleries remain private
