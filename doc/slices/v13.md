# VS-13 — Notifications & Email Automation

## 1. Goal

Build a reliable notification and email automation system for the photography website.

This slice will ensure that:

* The photographer receives new enquiry notifications.

* Visitors receive enquiry confirmation emails.

* Admin receives important system notifications.

* Email templates can be managed without code.

* Email delivery status can be tracked.

* Failed emails can be retried safely.

* Notification settings remain configurable for different photographers.

This completes the communication loop after VS-10 — Contact / Enquiry Management.

```
Visitor submits enquiry
        ↓
Enquiry saved
        ↓
Notification event created
        ↓
Photographer receives email
        ↓
Visitor receives confirmation
        ↓
Admin manages enquiry
        ↓
Status update notification
```

# 15. Template Business Rules

### Rule 1

Each notification type should have one active template.

### Rule 2

If a custom template is empty or invalid, use the default template.

### Rule 3

Admin can restore the default template.

### Rule 4

Template variables must be validated before saving.

### Rule 5

Unknown variables should generate a warning or validation error.

### Rule 6

Templates must be escaped safely to prevent HTML injection.

# 18. Background Email Processing

Email sending should not block the enquiry submission request.

### Incorrect flow

```
Visitor submits form
        ↓
Send email
        ↓
Save enquiry
        ↓
Response
```

### Recommended flow

```
Visitor submits form
        ↓
Save enquiry
        ↓
Create notification job
        ↓
Return success response
        ↓
Background worker sends email
```

This makes the contact form faster and more reliable.

# 19. Retry Rules

Recommended retry attempts:

```
Attempt 1 — Immediately
Attempt 2 — After short delay
Attempt 3 — After longer delay
```

After the final failure:

```
Mark as FAILED
Create admin alert
```

Retry only temporary failures such as:

* Provider timeout

* Temporary network failure

* Rate limit response

* Temporary provider outage

Do not repeatedly retry permanent errors such as invalid email addresses.

# 27. Edge Cases

### Email provider not configured

Enquiry should still be saved successfully. Create a failed or blocked notification log and show an admin warning.

### Visitor email is invalid

Save the enquiry if server validation permits the submission, but do not retry the visitor email indefinitely.

### Admin email unavailable

Use a configured fallback recipient if available.

### Duplicate notification event

Use an idempotency key based on:

```
entity_id + notification_type
```

where appropriate.

### Visitor submits multiple times

Prevent duplicate emails through rate limiting and duplicate submission protection.

### Template contains unsupported variable

Reject or warn before saving.

### Email provider times out

Queue a retry.

### Admin deletes an enquiry

Retain the notification log according to the project’s retention policy, or anonymize it if required.

# 28. Security Requirements

* Protect all notification management routes.

* Never expose SMTP passwords or API keys.

* Sanitize HTML email content.

* Escape template variables.

* Do not expose internal notes to visitors.

* Do not include admin URLs in visitor emails.

* Do not allow arbitrary template scripts.

* Rate-limit test email functionality.

* Restrict notification logs to authorized admins.

* Avoid logging full enquiry messages unnecessarily.

* Protect email addresses from public API exposure.
