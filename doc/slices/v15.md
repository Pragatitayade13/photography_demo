# 4. Business Logic

## 4.1 Image Upload Flow

```
Admin uploads image
        ↓
Validate file type and size
        ↓
Scan file metadata and extension
        ↓
Generate safe filename
        ↓
Store original privately
        ↓
Generate optimized versions
        ↓
Generate thumbnails
        ↓
Save media metadata
        ↓
Mark media as ready
        ↓
Make public only if approved
```

## 4.2 Image Visibility Rules

Each media item must have a visibility state:

* `PUBLIC`

* `PRIVATE`

* `DRAFT`

* `ARCHIVED`

### Public media

Can be displayed on:

* Homepage

* Portfolio

* Project pages

* About page

* Public galleries

* Social sharing previews

### Private media

Can only be accessed through an authorized private route or signed URL.

### Draft media

Can be viewed by admins but not by public visitors.

### Archived media

Should not appear in public results or normal admin selections unless explicitly filtered.

## 5.4 Optimization Rules

* Do not serve original images to normal public cards.

* Use responsive image sources.

* Use `srcset` and `sizes`.

* Lazy-load images below the fold.

* Eager-load only the main hero image.

* Preserve image quality while reducing file size.

* Prevent layout shift by storing image dimensions.

* Use placeholders while large images load.

* Do not optimize the same image repeatedly.

* Regenerate variants only when the source image changes or settings change.

# 6. Database Schema

## 6.1 `media_assets`

SQL

```
CREATE TABLE media_assets (
    id UUID PRIMARY KEY,
    original_filename VARCHAR(255) NOT NULL,
    stored_filename VARCHAR(255) NOT NULL UNIQUE,
    mime_type VARCHAR(100) NOT NULL,
    file_extension VARCHAR(20) NOT NULL,
    file_size BIGINT NOT NULL,
    width INTEGER,
    height INTEGER,
    aspect_ratio DECIMAL(10, 4),
    storage_path TEXT NOT NULL,
    visibility VARCHAR(20) NOT NULL DEFAULT 'DRAFT',
    processing_status VARCHAR(30) NOT NULL DEFAULT 'PENDING',
    processing_error TEXT,
    alt_text TEXT,
    caption TEXT,
    uploaded_by UUID,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

## 6.2 `media_variants`

SQL

```
CREATE TABLE media_variants (
    id UUID PRIMARY KEY,
    media_id UUID NOT NULL REFERENCES media_assets(id) ON DELETE CASCADE,
    variant_name VARCHAR(50) NOT NULL,
    width INTEGER NOT NULL,
    height INTEGER NOT NULL,
    mime_type VARCHAR(100) NOT NULL,
    file_size BIGINT NOT NULL,
    storage_path TEXT NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE(media_id, variant_name)
);
```

## 6.3 `security_logs`

SQL

```
CREATE TABLE security_logs (
```

# 7. Media Processing Status

Allowed values:

```
PENDING
PROCESSING
READY
FAILED
RETRY_REQUIRED
```

## Processing Rules

* Uploaded files begin with `PENDING`.

* A background process changes the status to `PROCESSING`.

* Successful variant generation changes it to `READY`.

* Any failure changes it to `FAILED`.

* Admin can retry failed processing.

* A failed image must not appear publicly.

* Original files should remain protected until processing succeeds.

# 9. Security Requirements

## 9.1 Authentication Security

* Protect all admin routes with authentication middleware.

* Validate access token/session on every protected request.

* Use secure, HTTP-only cookies where cookie authentication is used.

* Use `SameSite` protection.

* Apply session expiration.

* Support logout from all sessions if possible.

* Do not store authentication secrets in frontend code.

* Do not expose password hashes.

* Do not return full user records unnecessarily.

* Log repeated failed login attempts.

* Temporarily block excessive login attempts.

## 9.2 Authorization

Every admin API must verify:

```
Is the user authenticated?
        ↓
Is the session valid?
        ↓
Does the user have the required role?
        ↓
Does the user have permission for this action?
```

Do not rely only on frontend route guards.

## 9.3 Input Validation

Validate all incoming values on the backend:

* UUIDs

* Slugs

* Email addresses

* Phone numbers

* Dates

* Numeric values

* Pagination values

* Sort fields

* File metadata

* Enum values

* Rich text content

* URLs

Reject unexpected fields where possible.

## 9.4 Input Sanitization

Sanitize:

* Project descriptions

* About content

* Testimonials

* Captions

* SEO descriptions

* Contact messages

* Admin notes

* Email template variables

Prevent:

* Stored XSS

* HTML injection

* Script injection

* Unsafe URL schemes

* Malicious event handlers

Allowed URL schemes should normally be limited to:

```
https
http
mailto
tel
```

## 9.5 File Upload Security

* Validate MIME type using file content, not only extension.

* Restrict maximum upload size.

* Generate server-side filenames.

* Do not use the original filename as the storage key.

* Reject executable content.

* Remove unsafe metadata where appropriate.

* Do not allow path traversal.

* Do not serve uploaded files from an executable directory.

* Prevent SVG script injection.

* Verify that the uploaded file is a valid image.

* Apply upload rate limits.

Additional indexes should be checked for:

* Project slug

* Project publication status

* Project featured status

* Enquiry status

* Enquiry created date

## Query Rules

* Always paginate large lists.

* Avoid returning unnecessary columns.

* Avoid N+1 queries.

* Use joins or batch queries for related data.

* Do not load all media records at once.

* Do not return original image metadata to public cards.

* Add query time logging for slow requests.

## Rules

* Never expose stack traces in production responses.

* Never expose SQL queries.

* Never expose environment variables.

* Never expose provider credentials.

* Show user-friendly messages on the frontend.

# 16. Frontend Performance Requirements

## 16.1 Public Website

* Use lazy loading for below-the-fold images.

* Use a responsive image component.

* Use fixed aspect-ratio containers.

* Avoid large blocking scripts.

* Load only required fonts and icons.

* Defer non-critical analytics.

* Use skeleton loaders for project grids.

* Avoid unnecessary re-rendering.

* Use pagination or infinite loading for large portfolios.

* Preload only the main hero image.

* Use compressed thumbnails for project cards.

## 16.2 Fullscreen Gallery

* Load the selected image first.

* Preload only the next and previous images.

* Do not load every high-resolution image immediately.

* Release unused image resources when the viewer closes.

* Display loading and error states.

* Preserve keyboard and touch navigation.

## 16.3 Admin Panel

* Paginate media and enquiry lists.

* Use server-side filtering.

* Avoid loading all dashboard data repeatedly.

* Cache stable configuration.

* Debounce search inputs.

* Show upload progress.

* Show processing status updates.
