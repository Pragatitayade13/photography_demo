# VS-14 — Advanced Portfolio Features & Client Experience

## 1. Goal

Enhance the public photography website with premium portfolio features that improve visitor engagement and help convert visitors into clients.

This slice will introduce:

* Advanced project filtering

* Project search

* Related projects

* Featured projects

* Before/after image comparison

* Fullscreen gallery viewer

* Image navigation

* Favorites or shortlist functionality

* Client-focused project presentation

* Improved enquiry conversion

* Project sharing enhancements

The goal is to make the portfolio feel like a premium photography experience, not a basic image gallery.

# 2. Business Objective

The visitor should be able to:

```
Discover photography
        ↓
Filter by interest
        ↓
Open a project
        ↓
Explore images deeply
        ↓
Save or share work
        ↓
View related projects
        ↓
Submit an enquiry
```

This slice improves both:

* User experience

* Business conversion

# 8. Search Functionality

Visitors can search by:

* Project title

* Project description

* Category

* Location

* Tags

* Photography type

Example searches:

```
wedding
portrait
Mumbai
editorial
pre-wedding
```

### Search rules

* Search should be case-insensitive.

* Empty search should show all visible projects.

* Search should only return published projects.

* Search should not expose draft or private projects.

* Search results should have a useful empty state.

Example empty state:

```
No projects found.

Try another keyword or explore all categories.
```

# 16. Gallery Viewer Behavior

### Desktop

* Left and right arrow navigation

* Escape closes viewer

* Arrow keys navigate images

* Mouse wheel should not accidentally change images

* Zoom should be controlled

### Mobile

* Swipe left for next image

* Swipe right for previous image

* Tap close button

* Pinch-to-zoom where supported

* Prevent page overflow behind the viewer

### Accessibility

* Focus should move into the viewer.

* Close button must be keyboard accessible.

* Images require meaningful alt text.

* Buttons must have accessible labels.

* Screen readers should announce image position.

# 19. Before/After Rules

* Both images are required.

* Images should have compatible dimensions.

* Only published projects can display comparisons.

* Comparison must be disabled if either image is missing.

* The slider must work with mouse, touch, and keyboard.

* Provide a non-drag alternative such as percentage buttons.

Example controls:

```
[Before] [50%] [After]
```

# 20. Favorites / Shortlist

# 28. Validation

### Search

* Maximum search length

* Trim whitespace

* Escape special characters

* Prevent query injection

### Related projects

* Cannot select the same project

* Cannot select duplicate projects

* Only valid projects allowed

### Comparison

* Before image required

* After image required

* Both media records must exist

* Only supported image formats allowed

### Featured projects

* Only published projects can be featured

* Featured order must be a positive integer

### Favorites

* Only valid public project IDs can be saved

* Limit shortlist size to prevent abuse

# 29. Edge Cases

### No related projects

Hide the related-project section.

### No search results

Show a helpful empty state.

### Project has only one image

Gallery viewer still works without navigation controls.

### Image fails to load

Show a fallback image and continue gallery navigation.

### Comparison image deleted

Automatically disable the comparison and notify admin.

### Project unpublished

Remove it from:

* Search

* Featured section

* Related projects

* Shortlists

* Sitemap

### Favorite project becomes unavailable

Show it as unavailable or remove it from the shortlist.

### Visitor opens an invalid project slug

Return a proper 404 page.

### Mobile gallery

Ensure the viewer does not create horizontal page scrolling.

# 30. Security Requirements

* Public APIs must return published content only.

* Validate all project IDs and slugs.

* Sanitize search parameters.

* Prevent unauthorized admin updates.

* Do not expose private client galleries.

* Do not expose original media URLs when access is restricted.

* Rate-limit public analytics and favorite endpoints.

* Validate comparison media ownership and project association.

* Prevent manipulation of featured order through unauthorized requests.

# 33. UAT Acceptance Criteria

VS-14 is accepted when:

* Visitors can search projects.

* Visitors can filter projects.

* Featured projects display in the correct order.

* Related projects are displayed correctly.

* Fullscreen gallery works on desktop and mobile.

* Image navigation works with buttons, keyboard, and touch.

* Image zoom works without breaking the layout.

* Before/after comparison works where configured.

* Visitors can save and remove favorite projects.

* Shortlist displays saved projects correctly.

* Project enquiry CTA passes project context to the contact form.

* Sharing uses the correct public project URL.

* Only published projects appear publicly.

* Analytics events are recorded safely.

* Admin can configure advanced project features.

* Existing portfolio, SEO, contact, and notification functionality continues working.
