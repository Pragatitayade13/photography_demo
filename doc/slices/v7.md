# VS-07 — Homepage Content Management

**Project:** Photography Showcase Website
**Vertical Slice:** VS-07
**Module:** Homepage Content Management / CMS
**Depends On:** VS-03 Admin Dashboard, VS-04 Category Management, VS-05 Photo Management, VS-06 Project/Gallery Management

---

## 1. Slice Goal

VS-07 gives the photographer complete control over the **public homepage** from the admin panel.

The photographer should be able to decide:

* What hero section visitors see
* Hero image/video
* Main headline
* Introduction text
* Featured projects
* Selected photographs
* Photography categories
* Photographer introduction
* Call-to-action sections
* Section visibility
* Section ordering
* Homepage preview
* Publish changes

The goal is:

> **The photographer should be able to completely update the homepage without changing code.**

# 7. Homepage Configuration Schema

Recommended:

```text
homepage_sections
```

| Field         | Type       |
| ------------- | ---------- |
| id            | UUID       |
| section_key   | VARCHAR    |
| title         | VARCHAR    |
| is_visible    | BOOLEAN    |
| sort_order    | INTEGER    |
| configuration | JSON/JSONB |
| created_at    | TIMESTAMP  |
| updated_at    | TIMESTAMP  |

Example:

```json
{
  "sectionKey": "featured_projects",
  "isVisible": true,
  "sortOrder": 3
}
```

---

# 8. Why JSON Configuration?

Different sections have different settings.

For example:

Hero:

```json
{
  "headline": "Stories Worth Remembering",
  "subheadline": "Wedding & Editorial Photographer",
  "mediaType": "image"
}
```

Featured Projects:

```json
{
  "projectIds": [
    "project-1",
    "project-2",
    "project-3"
  ],
  "displayLimit": 3
}
```

CTA:

```json
{
  "title": "Let's Create Something Beautiful",
  "buttonText": "Contact Me"
}
```

A JSON/JSONB configuration keeps the CMS flexible.

# 31. Draft vs Published Homepage

Use:

```text
Draft configuration
Published configuration
```

Workflow:

```text
Edit
 ↓
Save Draft
 ↓
Preview
 ↓
Publish
 ↓
Public Website
```

This is much better than immediately changing the live website every time the photographer edits something.

Recommended architecture:

```text

```

```text

```

```text

```

# 33. Save vs Publish

Two different actions:

```text
[ Save Draft ]
[ Preview ]
[ Publish ]
```

### Save Draft

Doesn't affect public website.

### Preview

Shows draft.

### Publish

Makes the draft live.

# 44. Important Business Rules

### BR-HOME-001

Only authenticated admins can manage homepage content.

### BR-HOME-002

Only one published homepage configuration should be active.

### BR-HOME-003

Draft changes must not affect the public website.

### BR-HOME-004

Hidden sections must not render.

### BR-HOME-005

Unpublished projects must not appear in Featured Projects.

### BR-HOME-006

Hidden projects must not appear publicly.

### BR-HOME-007

Deleted photos must be removed from Selected Work automatically.

### BR-HOME-008

Deleted projects must be removed from Featured Projects.

### BR-HOME-009

Duplicate project selection must be prevented.

### BR-HOME-010

Duplicate photo selection must be prevented.

### BR-HOME-011

Section ordering must persist.

### BR-HOME-012

Only valid internal routes should be accepted for internal CTAs.

# 45. Automatic Cleanup

This is important.

Suppose:

```text
Featured Projects
    ↓
Royal Wedding
```

Then admin deletes:

```text
Royal Wedding
```

The homepage should automatically remove it from:

```text
homepage_featured_projects
```

Similarly:

```text
Selected Work
    ↓
Photo 12
```

Photo 12 gets deleted.

System removes its homepage relationship.

This prevents broken homepage content.

# 63. UAT — Project Integration

**Given:** A published project exists.

**When:** Photographer adds it to Featured Projects.

**Then:** It should appear in the Featured Projects preview and public homepage after publishing.

---

# 64. UAT — Deleted Project

**Given:** A project is currently featured.

**When:** The project is deleted from Project Management.

**Then:** It must not produce a broken card on the homepage.

---

# 65. UAT — Mobile

**Given:** Photographer opens Homepage Management on a mobile device.

**Then:** All CMS functions should remain usable without horizontal scrolling.
