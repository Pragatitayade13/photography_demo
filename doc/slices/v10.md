# VS-10 — Contact / Enquiry Management

**Project:** Photography Showcase Website
**Vertical Slice:** VS-10
**Module:** Public Contact + Admin Enquiry Management
**Depends on:** VS-02 Admin Authentication, VS-03 Admin Dashboard, VS-06 Project/Gallery Management, VS-08 Public Portfolio, VS-09 Photographer About/Profile

---

# 1. Slice Goal

VS-10 completes the **main business conversion flow** of the website.

A visitor who likes the photographer's work should be able to easily contact them and submit an enquiry.

The photographer should then be able to manage those enquiries from the admin panel.

### Complete journey

```text
Visitor
   ↓
Homepage
   ↓
Portfolio
   ↓
Project
   ↓
About
   ↓
"I'd like to work with you"
   ↓
Contact Form
   ↓
Submit Enquiry
   ↓
Success Confirmation
   ↓
Photographer receives enquiry
   ↓
Admin Panel
   ↓
View Enquiry
   ↓
Update Status
   ↓
Respond / Follow Up
```

---

# 41. Spam Protection

This is important because a public contact form will eventually receive bots.

Implement a layered approach:

```text
Rate limiting
+
Honeypot field
+
Server-side validation
+
Optional CAPTCHA/Turnstile
```

Don't make CAPTCHA mandatory for every visitor unless needed.

---

# 42. Rate Limiting

Example:

```text
Maximum:
5 submissions / IP / hour
```

Exact production limits should be configurable based on deployment.

Return a generic message if rate-limited.

---

# 43. Honeypot

Include an invisible field:

```text
website
```

Normal visitors leave it empty.

If a bot fills it:

```text
Reject / silently discard
```

---

# 44. Duplicate Enquiry Protection

If someone accidentally clicks Submit twice:

```text
Request 1 → accepted
Request 2 → detected
```

Use an idempotency mechanism where appropriate.

# 66. Business Rules

### BR-ENQ-001

Only active enquiry types can be selected.

### BR-ENQ-002

Required fields must pass server-side validation.

### BR-ENQ-003

Consent must be explicitly accepted where required.

### BR-ENQ-004

Every accepted enquiry receives a unique reference number.

### BR-ENQ-005

New enquiries default to `NEW`.

### BR-ENQ-006

New enquiries default to `NORMAL` priority.

### BR-ENQ-007

Admin notes are private.

### BR-ENQ-008

Enquiry activity is immutable.

### BR-ENQ-009

Only authorized admins can view enquiries.

### BR-ENQ-010

Public users cannot retrieve enquiry records.

### BR-ENQ-011

Duplicate submissions should be minimized/prevented.

### BR-ENQ-012

Rate limiting must protect the public endpoint.

### BR-ENQ-013

Inactive enquiry types cannot receive new enquiries.

### BR-ENQ-014

Deleting an enquiry type must not corrupt historical enquiries.

### BR-ENQ-015

Hidden/private contact details must not appear publicly.

**Given:** Photographer adds a private note.

**When:** Visitor accesses the website.

**Then:** The visitor must never be able to see that note.

---

# 74. UAT — Spam Protection

**Given:** A client submits the form repeatedly.

**When:** The configured rate limit is exceeded.

**Then:** Further requests should be temporarily rejected or throttled.

---

# 75. UAT — Mobile

**Given:** Visitor is using a smartphone.

**When:** They open `/contact`.

**Then:**

* Form fits screen
* Inputs are usable
* Date selector works
* Submit button is accessible
* Validation works
* No horizontal scrolling occurs
